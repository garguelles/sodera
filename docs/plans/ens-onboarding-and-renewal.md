# ENSv2 onboarding and annual renewal

Status: first controlled user-owned ENSv2 subname confirmed on Sepolia; real-name onboarding is pending and renewal is deferred until after the hackathon.

## Product decision

Give each wallet user one real `<username>.sodera.eth` identity on the **current Ethereum Sepolia ENSv2 beta deployment**. The name is an ENSv2 ERC1155Singleton token owned by the user's passkey-controlled Kernel smart account. Deploy a standard ENS `PermissionedResolver` for that Kernel, granting record and resolver authority only to it. A Sodera-owned resolver-only alias does not meet this ownership requirement. The historical ETHOnline deployment in [PRA-206](../research/PRA-206-ensv2-namespace.md) is not the current hierarchy.

New names last one year and have a **zero Sodera registration price**. **Hackathon scope:** no renewal path or `ROLE_RENEW` grant is live; names can expire after one year. Revisit the following planned renewal policy **after the hackathon**: zero Sodera renewal price (Sepolia gas still applies), open renewal during the last 90 days, extend the current expiry by one year, and allow anyone to call a bounded renewal contract with self-funded gas or bounded sponsorship. Reject renewals of unavailable names, extensions beyond the parent's expiry, and repeated early extensions. Monitor and renew `sodera.eth` first where necessary. ENSv2 has no automatic grace period: expiry immediately interrupts identity and an expired label can be registered by someone else. Do not promise automatic or permanent names.

The owner controls `0x7Ed08e45067d7Bb1c064055eC99aCD6586453915`. They deployed and mounted child registry `0xfBb4ef18Db7F8044a0A19fD1Db7B192327811EC7` on Sepolia and granted `ROLE_REGISTRAR` only to the separate issuer. A [controlled device claim](../research/ensv2-sepolia-namespace-check.md#controlled-user-claim) confirmed that `gargslocalone.sodera.eth` is a token owned by the phone's Kernel and resolves to that Kernel through an official per-account resolver. No renewal role is configured, and Home still displays its fixture name until the real identity flow is integrated. ENS warns that its Sepolia beta state may be reset periodically; deployment addresses and name state must be revalidated before a release or demo.

## Architecture and trust boundaries

- Deploy one standard `UserRegistry` proxy via the current ENS Verifiable Factory. Set its canonical parent to the current `.eth` registry and mount it under `sodera.eth`. Pin the deployed factory, implementations, ABIs, Universal Resolver, initializer calldata, and role bitmap from current sources. Do not reuse ETHOnline addresses.
- An authenticated, operator-controlled issuer holds **only** root `ROLE_REGISTRAR`. It enforces username policy, one active Sodera name per Kernel *in the product*, abuse limits, request serialization, idempotency and a global issuance budget. These are service rules, not on-chain personhood or transfer restrictions. The combined public ENS/Uniswap `api/` must delegate signing to a private issuer worker with its own secret boundary; the keyless `agent/` planner remains separate. No issuer private key belongs in the public API, mobile app, static landing site or local ENS owner tool.
- For each claim, deploy an official factory resolver proxy with only the Kernel as grant recipient and set coin type `60` for the full DNS-encoded name to the same Kernel. Register with zero child-registry pointer and the exact name-scoped owner bitmap in [ADR-0011](../adr/0011-ensv2-user-subnames.md). Do not give the issuer resolver rights or ERC-1155 operator approval.
- A small, reviewed renewal contract holds only root `ROLE_RENEW`, checks registered state, the 90-day window, one-year extension and parent expiry on chain, and requires no name price. Anyone may pay gas to call it. Limit sponsored renewal independently through the existing sponsorship service; do not put a sponsor credential in client code.
- After a controlled end-to-end claim, verify registry provenance, child root roles and unauthorized-action reverts before revoking dangerous child root roles and locking its canonical-parent pointer. The `sodera.eth` ancestor can redirect the subtree until its name-scoped subregistry pointer authority and all other effective holders/operators are removed. Ask the parent owner to review and explicitly approve that **irreversible** step separately; never describe identities as fully emancipated based only on `UserRegistry.isEmancipated()`.

## Implementation order

1. **Read-only deployment gate.** Verify chain ID `11155111`, the parent's current `REGISTERED` state/owner/expiry, `.eth` and root pointers, operator/role holders, implementation provenance and ENSv2 Universal Resolver behavior. Record evidence and exact addresses separately from application defaults. Stop if ownership or canonical traversal disagrees with the user's expectation.
2. **Claim-authentication proof — new challenge version verified on Android.** With PostgreSQL configured, `api/` issues five-minute one-time challenges bound to chain, registry, account and label, atomically consumes them and verifies a user-verified WebAuthn assertion against a deployed Kernel's pinned implementation, root validator, on-chain P-256 key, RP and origin. A separate ten-minute opaque proof token is stored as a hash. Concurrent/replay tests passed against PostgreSQL. The latest version also hashes the chain, registry, account, label, expiry and random nonce into the signed challenge so the private worker can reject a relabeled proof. The owner reported Step 5 passing on the connected Android device, and [independent local evidence](../research/ensv2-sepolia-namespace-check.md#android-claim-proof) confirms the nonce-bound challenge was consumed and verified for the deployed Kernel. This diagnostic does **not** issue a name. An arbitrary `signMessage`/ERC-1271 challenge is not established, and a client-supplied address or public app token alone is never sufficient.
3. **Owner-reviewed registry setup — complete.** The owner used the [standalone local MetaMask owner app](../../ens/README.md) for separate, receipt-checked transactions. The owner has only `ROLE_SET_PARENT`, `ROLE_REGISTRAR_ADMIN`, and `ROLE_RENEW_ADMIN` on the child. Retain the latter two under the owner's control to grant/revoke a registrar and renewal principal as needed; review operational key-rotation and retained admin trust before public issuance. Revoking `ROLE_SET_PARENT` after testing is a separate irreversible operation, as is locking the ancestor pointer. Do not rerun `pnpm prepare:registry` against the already mounted namespace. See [deployment evidence](../research/ensv2-sepolia-namespace-check.md#mounted-child-registry).
4. **Idempotent claim service — controlled flow verified.** `api/src/ens/` and `api/src/issuer/` atomically redeem single-use proofs, maintain a durable claim ledger and one active name per wallet/label, and run a leased private worker that independently re-verifies the stored assertion and cryptographic chain/account/label/expiry challenge binding. The public API opens claim routes only while the issuer holds exactly `ROLE_REGISTRAR`; no private key is loaded in the shared ENS/Uniswap API. Concurrent redemption, fresh-proof recovery, conflicts, interrupted transactions and owner mismatches have tests against local PostgreSQL and fake chain adapters. The first real Android claim reached `confirmed` in the database and on Sepolia. The worker rejects the public synthetic test Kernel. Hackathon mode permits successive fresh wallets and labels without a daily claim cap while keeping short-window challenge limits; wider production issuance needs an approved global budget and the exact product reserved list.
5. **Resolver and ownership confirmation — first live claim passed.** The private worker factory-deployed an official resolver with only the Kernel's address/text/link/upgrade authority and ETH coin-60 record, then registered `gargslocalone` for one year with the approved per-name bitmap. Independent checks confirmed successful issuer receipts, Kernel ERC-1155 ownership, the exact name roles, official resolver implementation, zero issuer resolver roles, zero child-registry pointer, and forward resolution to the Kernel. See [controlled user claim evidence](../research/ensv2-sepolia-namespace-check.md#controlled-user-claim). Repeat with a separate fresh wallet/label before relying on this flow for hackathon demos; do not use the diagnostic flow as evidence that real-name onboarding or renewal is complete.
6. **Onboarding and identity UI.** Replace `app/src/onboarding/onboarding.ts`'s mock claim and `app/src/components/onboarding-screen.tsx`'s hardcoded `anon.sodera.eth` with choose/check/claim/pending/reconcile/confirmed states. Version persisted profiles; preserve existing wallet identities and label mock-era profiles unverified. Restore pending claims after restart without duplicating transactions. Finish onboarding as a verified ENS identity only after chain confirmation. Recover Wallet reuses the same Kernel and rechecks its name rather than issuing a second one.
7. **Product integration.** Replace the fixed name in `app/src/wallet/wallet-home-live.ts` with verified chain state. Refresh on app foreground and before identity-sensitive operations; use an address-only fallback when a name transfers, expires, loses its canonical path, or no longer resolves to the current Kernel. Audit `app/src/wallet/send-transfer.ts` so recipient reads and confirmation use the current ENSv2 Universal Resolver and bind approval to the exact resolved address. Route future avatar writes through the Kernel-authorized operation lifecycle and the name's *current* resolver.
8. **Renewal path — after the hackathon.** Deploy/test the restricted renewal contract, authorize only that contract for root renewal, and remove unintended renewal principals. Expose renewal status and transaction review in-app. Show notices at 90, 30 and 7 days before expiry, plus explicit expired/parent-expired states. Renewing changes neither wallet ownership nor resolver records. No renewal endpoint, user action or guarantee is part of the current hackathon demo.

## Verification and launch gates

- Exercise a fresh Android create-wallet → confirmed name → Home flow and an interrupted/restarted registration; confirm no duplicate issuance and no mock name presented as real.
- Prove Kernel ownership and per-account resolver authority; simulate owner-permitted and issuer-forbidden record/resolver/transfer actions. Verify factory implementation, initializer grants, proxy events and public transaction links.
- **Post-hackathon:** test normal renewal, a second attempt outside the 90-day window, parent-too-short, changed ownership, expiry and self-funded fallback. Confirm a failed renewal never blocks wallet access.
- Test external transfer, loss of resolver/canonical path, and reinstall/recovery retaining the same Kernel. Verify the wallet shows an address instead of a falsely verified name.
- Run relevant TypeScript, lint, and focused authorization/idempotency tests and gather live Sepolia receipts. Recheck parent lifetime and beta deployment availability before demonstrating the feature.
